md: bound raid_disks by MD_SB_DISKS for v0.90 metadata

commit 1a33a379e6 ("md: reject v0.90 arrays with too many devices")
bounded sb->raid_disks in super_90_load(), so a crafted superblock can
no longer describe more devices than a v0.90 superblock is able to hold.
mddev->raid_disks however is not only loaded from the superblock.

Both the raid_disks sysfs attribute and MD_SET_ARRAY_INFO write it
directly while the array has no personality, and neither enforces the
v0.90 limit.  super_90_sync() then lays out the in-superblock device
table using mddev->raid_disks and walks past the end of the 4 KiB
superblock page.

Reject raid_disks values that a v0.90 superblock cannot represent, in
raid_disks_store() when v0.90 metadata is already selected, and in
metadata_store() when it is selected afterwards, so both orderings are
covered.  Clamp super_90_sync() as well so an array which already
carries a larger value cannot walk past sb->disks[].

The limit only applies when major_version is 0, so v1.x arrays, which
do not use the in-superblock device table, are unaffected.
